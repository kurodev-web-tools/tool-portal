# 初期MVP計画

## Summary

無料で始められる構成を前提に、初回は `Cloudflare Pages` で公開する `認証なしの最小ポータル + スケジュールカレンダー1本` を作る。  
ポータルは「今後ツール群が増えていく入口」として見せつつ、実利用できる機能はスケジュールカレンダーに集中させる。  
データ保存は `localStorage` を使い、外部API・有料API・サーバー必須機能は初回MVPから外す。

## Implementation Changes

### 1. プロダクト方針の再定義

- 既存の資料群はアイディア資産として保持し、初回実装対象は `スケジュールカレンダー` のみに限定する
- 既存のポータル設計にある `ログイン状態・課金プラン・利用回数表示` は初回MVPでは採用しない
- 初回ポータルは以下の役割だけを持たせる
  - ツール群の概要表示
  - ツール一覧表示
  - 実装済みツールへの導線
  - 未実装ツールの準備中表示

### 2. 初回MVPの画面構成

- ルート `/` はポータルTOPにする
- ポータルTOPには以下を置く
  - サービス概要
  - カテゴリまたはスイート単位のカード一覧
  - 実装済みの `スケジュールカレンダー` への導線
  - 他ツールのプレースホルダカード
- `スケジュールカレンダー` は独立ページで実装する
- ポータル内の未実装ツールカードは遷移不可または準備中ページ遷移に統一する

### 3. スケジュールカレンダーMVP仕様

- 初回機能は以下に限定する
  - 予定の登録
  - 予定の編集
  - 予定の削除
  - 予定一覧表示
  - カレンダー表示
  - 投稿文コピー
  - `X` 投稿画面への遷移
- 投稿導線は API 投稿ではなく、共有リンクまたは投稿画面オープンで実現する
- データ保存は `localStorage` のみとし、アカウント同期・複数端末同期は未対応にする
- 予定データの最低項目は以下とする
  - id
  - title
  - date
  - time
  - category
  - platform
  - note
- 投稿補助はテンプレート置換ベースにし、初回は `X中心 + 汎用コピー` のみ提供する
- 画像生成、SNS API連携、Google Calendar連携、自動最適化AIは初回では実装しない

### 4. 技術構成

- 技術スタックは `Next.js 15 + TypeScript + Tailwind CSS`
- 初回はフロントエンド完結構成にする
- デプロイ前提は `Cloudflare Pages`
- 将来認証が必要になった場合は、次段階で以下のどちらかに拡張する
  - Pages Functions を追加
  - Workers + D1/KV を追加
- 初回MVPではこの拡張余地だけ残し、認証基盤は実装しない

### 5. 実装前に先に整えるドキュメント

- `task.md`
  - 今回の即時実行対象を `ポータルMVP` と `スケジュールカレンダーMVP` に固定する
- `docs/PLAN.md`
  - Phase 1: 認証なしポータル + カレンダー
  - Phase 2: Cloudflare保存・認証
  - Phase 3: ツール追加
- `README.md`
  - リポジトリ概要、初回MVPの範囲、起動手順、公開方針を記載する
- 既存のポータル仕様/設計は削除せず、将来版と無料MVP版を分けて扱う

## Test Plan

- ポータルTOP
  - 実装済みツールカードが正しく遷移する
  - 未実装カードが準備中表示になる
  - モバイルとPCで主要導線が崩れない
- スケジュールカレンダー
  - 予定を追加すると表示と保存が反映される
  - リロード後も `localStorage` から復元される
  - 編集と削除が正しく反映される
  - 不正入力時に最低限のバリデーションが効く
  - コピー機能で投稿文が取得できる
  - `X` ボタンで想定フォーマットの投稿画面へ遷移できる
- デプロイ
  - `Cloudflare Pages` 想定の静的公開で主要画面が動作する
  - サーバー必須機能が混入していないことを確認する

## Assumptions

- 初回MVPの目的は「無料で実用品を1本出し、今後のツール群へ広げる入口を作ること」
- `投稿するボタン` は API 投稿ではなく、`X投稿画面へ遷移 + クリップボードコピー` を意味する
- 認証、課金、利用回数管理、Google Calendar連携、AI生成系は Phase 2 以降に回す
- 既存の Cloudflare 環境は公開先として利用できるが、初回は高度なサーバー機能を前提にしない
