# 初回MVP デザイン・実装計画

## Summary

初回MVPは `Cloudflare Pages` 前提の `認証なしポータル + スケジュールカレンダー1本` で進める。  
データ保存は `localStorage`、投稿導線は `X遷移 + コピー` に限定し、外部APIや課金要素は入れない。  
見た目は全体として `実務ダッシュボード寄り`、`ライト / ダーク切替対応` を前提にする。

## Implementation Changes

### 1. ポータルのデザイン仕様

- ルート `/` をポータルTOPにする
- レイアウトは `上部ヘッダー + カードグリッド中心 + 軽いフィルタ列`
- ヘッダーには以下を置く
  - サービス名
  - ライト / ダーク切替
  - 必要最小限のナビゲーション
- ヒーロー領域は `導入文 + 軽いサマリー`
  - 実装済みツール数
  - 準備中ツール数
  - カテゴリ数
- フィルタは `カテゴリ + 実装状態`
- ツールカードは `中型カード`
  - ツール名
  - 短い説明
  - 実装状態
  - 導線ボタン
- 実装済みは `スケジュールカレンダー` のみ遷移可能にする
- 未実装ツールは `準備中` 表示に統一する

### 2. スケジュールカレンダーのデザイン仕様

- 配置は `左カレンダー + 右サイドパネル`
- 初期表示は `週表示`
- 表示切替は `月 / 週 / 日`
- 右サイドパネルはタブ切替
  - `予定管理`
  - `投稿補助`
- `予定管理` タブで扱う内容
  - 選択日の予定一覧
  - 新規登録導線
  - 編集 / 削除導線
- `投稿補助` タブで扱う内容
  - テンプレ選択
  - 投稿文プレビュー
  - コピー
  - `X` 投稿画面への遷移
- 見た目は `実務カレンダー寄り`
- モバイルでは右パネルを下段またはモーダル寄りに崩してよい

### 3. 初回MVPの機能範囲

- 実装対象
  - ポータルTOP
  - ツール一覧表示
  - カテゴリ / 実装状態フィルタ
  - スケジュールカレンダー本体
  - 予定の登録 / 編集 / 削除
  - `localStorage` 保存と復元
  - 投稿補助テンプレ選択
  - 投稿文コピー
  - `X` 投稿画面遷移
- 初回では実装しない
  - ログイン
  - 課金
  - 利用回数表示
  - Google Calendar連携
  - SNS API直接投稿
  - AI生成機能
  - 複数端末同期

### 4. 実装前に保存する運用資料

- `task.md`
  - 現在作業を `ポータルMVP` と `スケジュールカレンダーMVP` に固定
- `docs/PLAN.md`
  - Phase 1: 認証なしポータル + カレンダー
  - Phase 2: Cloudflare保存 / 認証
  - Phase 3: 他ツール追加
- `README.md`
  - リポジトリ概要、初回MVP範囲、起動手順、公開方針
- 既存のポータル仕様/設計書は参考資料として残し、無料MVP版の方針とは切り分ける

## Test Plan

- ポータル
  - ライト / ダーク切替が主要画面で崩れない
  - カテゴリ / 実装状態フィルタが正しく反映される
  - 実装済みカードだけが有効遷移になる
  - 未実装カードが準備中状態として分かる
- スケジュールカレンダー
  - 予定の追加 / 編集 / 削除が反映される
  - リロード後も `localStorage` から復元される
  - 初期表示が週表示になる
  - 右パネルの `予定管理 / 投稿補助` タブが切り替わる
  - テンプレ適用後の投稿文がコピーできる
  - `X` 投稿画面遷移に必要な文面が渡る
- 公開
  - `Cloudflare Pages` 前提の静的公開で主要導線が成立する

## Assumptions

- 合意済みプランは実装前の運用資料として扱う
- 初回MVPは「無料で使える実用品を1本出し、今後のツール群の入口を示す」ことが目的
- 投稿導線の `投稿するボタン` は API 投稿ではなく、`X投稿画面遷移 + コピー` を意味する
- 認証や同期が必要になったら、次段階で `Pages Functions` または `Workers + D1/KV` に拡張する
