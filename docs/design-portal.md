# Portal Design

## Overview

ポータルは「ツール群の入口」として機能する。  
初回MVPでは、サービスの全体像を見せつつ、実際に触れるツールは `スケジュールカレンダー` に集中させる。

見せ方の軸は以下。

- 実務ダッシュボード寄り
- 一覧性優先
- 初見で何があるか分かる
- 未実装ツールも将来性として自然に見せる

## Layout

### Overall Structure

- 上部ヘッダー
- 左サイドバー
- 右メインコンテンツ

左サイドバーは `ショートカット導線`、右メインは `全体一覧と探索` を担う。

### Header

- 左: サービス名またはロゴ
- 右: ライト / ダーク切替

ヘッダーは常時薄い境界線で区切り、重くしない。

### Left Sidebar

- 初期MVPでは `固定項目 + 実装済みツール` を表示する
- 固定項目の例
  - Home
  - Tools
- 実装済みツールの例
  - Schedule Calendar
- サイドバーは管理ツリーではなく、`よく使う導線` に見える軽さを保つ
- 将来的に `Pinned` `Recent` `Favorites` を追加できる余地を残す

### Main Content

- ヒーロー
- フィルタ列
- ツール一覧グリッド

メイン領域はツール探索の主役であり、サイドバーはこれを置き換えない。

### Hero

- 短い導入文
- 軽いサマリー
  - 実装済みツール数
  - 準備中ツール数
  - カテゴリ数

ヒーローはLPのように大きく見せず、ポータル全体の文脈を整える程度に留める。

### Filter Row

- 横並びチップ / セグメント型
- フィルタ対象は `カテゴリ` と `実装状態`
- 常設表示だが高さは抑える

### Grid

- 3列基準の安定グリッド
- 実装数が増えても4列に調整しやすい最小幅設計を前提にする
- カード高さは極端に揃えすぎず、短説明に収まる範囲で整理する
- サイドバー込みでも一覧性が落ちない幅バランスにする

## Cards

各カードは以下の要素で構成する。

- ツール名
- 短説明
- 状態ラベル
- 導線ボタン

### State Handling

- 実装済み: 明確な導線を表示
- 準備中: ボタン文言や状態ラベルで未実装を明示

カードは情報重視で、アイキャッチ画像なしでも成立する設計にする。  
必要であれば小さなアイコンやカテゴリ印を添えるが、主役にはしない。

## Visual Tone

- 背景は落ち着いた面でまとめる
- カードはフラット、境界線で整理
- アクティブフィルタと実装済み導線に深めティールを使う
- 準備中表示は中立色で抑える

## Responsive Behavior

- PC: 3列グリッドを優先
- Tablet: 2列
- Mobile: 1列
- モバイルでもフィルタは横スクロール可能なチップ列で維持してよい

## Key Components

- PortalHeader
- PortalSidebar
- PortalHeroSummary
- PortalFilterBar
- ToolCard
- StatusBadge

## Do

- 触れるツールと将来追加予定を一画面で理解できるようにする
- サイドバーをショートカットとして軽く見せる
- ポータルを過剰に演出しない
- 情報の優先順位を固定する

## Do Not

- サイドバーを全件一覧の代替にする
- 未実装ツールを実装済みに見せる
- カードの装飾差を強くしすぎる
- フィルタを複雑にしすぎる
