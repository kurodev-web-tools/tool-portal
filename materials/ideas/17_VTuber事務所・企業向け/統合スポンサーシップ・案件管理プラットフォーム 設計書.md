# 統合スポンサーシップ・案件管理プラットフォーム 設計書

## 1. システム構成図
- **フロントエンド (Web)**: 事務所の営業担当やマネージャーが利用するウェブアプリケーション。
- **バックエンド（APIサーバー）**: 案件データ、タレント情報、契約内容、パフォーマンスデータなどのCRUD操作、および外部APIとの連携を担う。
- **データベース**: 案件に関わる全ての情報を格納するリレーショナルデータベース。
- **外部API**: YouTube Data API, X API, Bitly API (短縮URL用) など。

### PC（ブラウザ）表示
- **カンバンボード形式の案件管理**: 案件を「リード」「交渉中」「準備中」「実施中」「完了」などのステージに分け、カードとしてドラッグ＆ドロップで管理できる。
- **案件詳細ページ**: 案件の概要、契約企業、報酬、担当タレント、成果物リスト、パフォーマンス結果などを一画面で確認できる。
- **タレントプロフィール**: 各タレントの過去の案件実績や、スケジュール、キャラクターシートなどを確認できる。

## 2. 主要機能詳細

### 2-1. 案件作成からタスク割り当てまで
- **ユーザーアクション**:
    1. 営業担当が、新しい案件情報をフォームに入力する（クライアント名、概要、予算、希望タレントの要件など）。
    2. マネージャーが、案件の要件に合うタレントをシステム内で検索し、アサインする。
    3. 契約内容に基づき、成果物（例:「〇月〇日 配信」）をタスクとして登録し、担当タレントに割り当てる。
- **システム動作**:
    1. 案件データ、タレントデータ、タスクデータがデータベース上で関連付けられて保存される。
    2. タスクが割り当てられると、担当タレント（またはそのマネージャー）に通知が飛ぶ。
    3. 各タスクには期限が設定され、カレンダービューで一覧表示できる。

### 2-2. パフォーマンス測定とレポート
- **ユーザーアクション**:
    - 案件登録時に、宣伝したいURLを入力すると、トラッキング用の短縮URLが自動で生成される。
    - 案件完了後、「レポート生成」ボタンを押す。
- **システム動作**:
    1. バックエンドが短縮URL APIを呼び出し、クリック数を定期的に取得・保存する。
    2. 成果物として登録された配信アーカイブや投稿のURLから、再生数や「いいね」数などをAPI経由で自動取得する。
    3. レポート生成時、これらの定量的データと、登録された契約内容を基に、テンプレートに沿ってレポート（PDFやWebページ）を自動生成する。

## 3. 技術スタック
- **フロントエンド**: **Next.js (React)**
- **UIフレームワーク**: **Tailwind CSS**, **shadcn/ui**
- **カンバンボード**: **react-beautiful-dnd**
- **バックエンド**: **Python (FastAPI)**
- **データベース**: **PostgreSQL**
- **外部連携**: **YouTube Data API**, **X API**, **Bitly API**

## 4. データベース設計
- **Clients**: 案件を依頼する企業の情報。
- **Projects**: 案件情報 (ClientID, ProjectName, Status, Budgetなど)。
- **Deliverables**: 成果物タスクの情報 (ProjectID, TalentID, TaskDescription, DueDate, Status, PostURLなど)。
- **PerformanceMetrics**: 成果物のパフォーマンスデータ (DeliverableID, Clicks, Views, Likesなど)。
- **TalentProfiles**: タレントのプロフィールと過去の実績。
