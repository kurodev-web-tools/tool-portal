# Schedule Calendar README

## Overview

`/tools/schedule-calendar` は、V Streamer Tools 初回 MVP の中核ツールです。
認証やサーバー保存を使わず、ブラウザの `localStorage` だけで予定管理、投稿補助、設定管理を完結します。

主な利用目的は、配信者・動画投稿者が日々の配信、制作、投稿、企画、準備、業務予定をまとめて確認し、投稿告知文まで素早く作ることです。

## Main Features

- 月 / 週 / 日表示のスケジュール確認
- 予定の追加、編集、削除、複製、ドラッグ移動（PCの週 / 日は日時移動、月は日付移動）
- PCの予定hover詳細プレビュー、1023px以下の予定詳細ボトムシート
- 削除、移動、編集保存後 8 秒以内の `元に戻す` undo toast
- 毎日 / 毎週の繰り返し予定作成
- 予定一覧タブ
  - タイトル検索
  - カテゴリ、媒体、期間フィルタ
  - 直近順、日付昇順、日付降順
  - フィルタ系ドロップダウンは独自メニューUI
- 投稿補助タブ
  - テンプレート選択
  - テンプレートの新規作成 / 編集 / 削除
  - テンプレート単位の用途カテゴリ、既定プラットフォーム、ハッシュタグ管理
  - 設定で保存したハッシュタグセットの選択追加
  - `{title}` などの変数挿入ボタン
  - 投稿文プレビュー
  - テンプレート側、保存済みセット、予定側のハッシュタグを結合したクリップボードコピー
  - X 投稿画面への遷移
  - サムネ作成 / SNS分割画像作成へのブラウザ内 handoff
- 予定管理フォーム
  - 予定ごとの告知文、告知ハッシュタグ、準備メモ、告知ステータス
  - 告知ハッシュタグ欄への保存済みハッシュタグセット追加（独自メニュー + 追加ボタン）
  - カテゴリ、プラットフォーム、告知ステータス、繰り返し、保存済みハッシュタグセットは独自メニューUI
- 設定タブ
  - 初期表示ビュー
  - 週開始曜日
  - 既定開始時刻
  - 既定所要時間
  - 投稿補助テンプレート管理
  - 保存済みハッシュタグセット管理
  - 設定内ドロップダウンは独自メニューUI
  - バックアップJSONの作成 / 復元
  - 全データ初期化

## Responsive Behavior

表示レンジは `ScheduleCalendarApp.tsx` 内の class 定数とコメントで明示しています。

- `<=1023px`: モバイル統合 UI
  - カレンダー、予定一覧、設定を下部タブで切り替える
  - 予定詳細 / 予定管理 / 投稿補助はボトムシートで表示する
  - 予定タップ時はまず詳細を表示し、`編集する` から予定管理フォームへ切り替える
  - 新規予定の保存成功後はボトムシートを自動で閉じる
  - 削除 undo toast は下部タブの上に固定表示する
- `1024-1279px`: タブレット 2 ペイン
  - 左にカレンダー、右に補助パネル
  - 右パネルは `予定管理 / 投稿補助 / 予定一覧 / 設定` の 4 タブ
- `>=1280px`: PC 2 ペイン
  - タブレット 2 ペインと同じ機能構成
  - 右パネル幅を広めに取り、一覧と設定の視認性を上げる

## Data Model And Storage

保存先は `localStorage` の `v-streamer-tools:schedule-calendar-events:v1` です。

保存 payload は versioned 形式です。

```json
{
  "version": 2,
  "events": [],
  "settings": {},
  "postTemplates": [],
  "hashtagSets": []
}
```

読み込み時は `normalizeStoragePayload()` を通して、旧形式の予定配列と versioned payload の両方を受け付けます。
壊れた JSON や import 失敗時は既存データを変更しない方針です。
旧データに `24:00` の終了時刻が残っている場合は、ブラウザの時刻入力で扱える `23:59` へ丸めます。

`events` は既存の予定基本項目に加えて、`announcementText`、`announcementHashtags`、`announcementMemo`、`announcementStatus` を持ちます。
`postTemplates` は `name`、`description`、`body` に加えて、`usageCategory`、`defaultPlatform`、`hashtags` を持ちます。
`hashtagSets` は投稿補助で横断利用する `name`、`hashtags` の組み合わせを持ちます。
旧データに告知準備フィールドやテンプレート拡張フィールドがない場合は、読み込み時に空文字または既定値で補完します。
保存 payload version は現時点では `2` のまま維持します。

削除 undo は一時的な React state のみで管理します。
undo 専用履歴は `localStorage` に保存しません。

## Tool Handoff

Schedule Calendar から Thumbnail Editor / SNS分割画像メーカーへ進む導線は、URLに本文を載せず、短い query token と `sessionStorage` の一時 payload で渡します。

保存キー接頭辞は `v-streamer-tools:tool-handoff:v1:`、URL query は `handoff` です。
SNS分割画像メーカーへは編集画面を直接開くため、`preset=split-4` も付与します。

Schedule Calendar 由来の handoff payload は version `1` で、次のテキスト情報だけを持ちます。

```json
{
  "version": 1,
  "source": "schedule-calendar",
  "target": "thumbnail-editor",
  "eventId": "event-...",
  "title": "配信タイトル",
  "date": "2026-05-03",
  "startTime": "20:00",
  "endTime": "21:00",
  "category": "stream",
  "categoryLabel": "配信",
  "platform": "YouTube",
  "announcementText": "告知文プレビュー",
  "hashtags": "#VTuber #配信告知",
  "announcementStatus": "copy-ready",
  "announcementStatusLabel": "投稿文準備済み"
}
```

Schedule Calendar 由来の payload では画像本体は渡しません。
payload は30分で期限切れ扱いにし、期限切れ、対象ツール不一致、壊れた JSON、token 不一致は安全に無視して通常起動します。
Thumbnail Editor は受け取ったタイトル、日時、告知文、カテゴリ / プラットフォームを、プリセット内の `見出し`、`時刻`、`サブ`、`ラベル` テキストへ初期反映します。
Schedule Calendar から遷移してきた場合は、プリセット変更やキャンバスサイズ変更をしても同じ予定テキストを新しいプリセットへ再適用します。
handoff 中のプリセット変更では、確認UI上でも予定テキストを引き継ぐ方針を明示し、プリセットを適用するたびに予定テキストを初期テキストとして再配置します。
通常起動時は主要テキストだけを新プリセットへ引き継ぐ選択肢がありますが、画像本体、図形、自由追加レイヤーの高度なマージは行いません。
SNS分割画像メーカーは告知文メモを表示し、出力ファイル名の初期値へ日付とタイトルを反映します。

Thumbnail Editor から SNS分割画像メーカーへ進む導線も、URLには短い `handoff` token と `preset=split-4` だけを載せます。
描画済みPNG相当の画像本体は `localStorage` へ保存せず、SNS分割画像メーカーのIndexedDB画像保存領域へ一時キーで保存します。
handoff payload には `source: "thumbnail-editor"`、`target: "sns-split-image-maker"`、`imageStorageId`、タイトル、日付、カテゴリ、プラットフォーム、告知文、ハッシュタグ、ファイル名候補を載せます。
SNS分割画像メーカーは token と一時画像の両方を正しく読めた場合だけ、画像を `base` 画像として反映し、既定で `split-4` 編集画面を開きます。
token 不一致、期限切れ、壊れた payload、対象ツール不一致、画像取得失敗は安全に無視して通常起動します。

繰り返し予定は保存時に複数の通常予定として作成します。
MVP範囲は `毎日` / `毎週` のみです。例外日、繰り返し終了日の詳細指定、シリーズ一括編集は未対応です。

## Privacy And Local Data Notes

- 予定、メモ、投稿補助テンプレート、保存済みハッシュタグ、設定はブラウザの `localStorage` に平文で保存されます。
- サーバー送信、アカウント同期、外部API連携は行いません。
- 共有端末や共用ブラウザプロファイルでは、利用後にブラウザ側のサイトデータ削除、または本ツールの全データ初期化を行ってください。
- JSON エクスポート内容にも予定、メモ、投稿補助テンプレート、保存済みハッシュタグが含まれるため、共有・保管時は取り扱いに注意してください。
- JSON インポートは、巨大データによるブラウザ停止や保存領域圧迫を避けるため、文字数・件数・主要テキスト長の上限を設けています。

## Backup And Recovery

通常のバックアップは、設定タブの `バックアップ作成` でJSONを出力し、別ファイルとして保管します。
復元時はJSONを入力欄へ貼り付け、`バックアップ復元` を実行します。

保存済みデータが壊れて読み込めない場合は、画面上部に読み込み失敗メッセージを表示し、初回の自動保存で既存 `localStorage` を上書きしないようにしています。
復旧手順は次の通りです。

1. 直近のバックアップJSONがある場合は、設定タブの `バックアップ復元` から復元する。
2. 復元JSONが拒否された場合、既存データは保持されるため、JSONの形式、件数、文字数上限を確認して再実行する。
3. バックアップがなく復旧できない場合のみ、設定タブの `全データ初期化` で初期状態へ戻す。

## Important UX Rules

- 予定削除は確認モーダルを出さず、削除後 toast の `元に戻す` で復元する
- 移動と編集保存も直近状態を toast の `元に戻す` で復元する
- PC週 / 日表示のドラッグ移動では `ここに移動 HH:MM - HH:MM` のガイドを表示し、drop後の時刻を事前に確認できるようにする
- PC表示では予定hoverで詳細プレビューを表示し、操作ボタンは置かない
- 1023px以下では予定タップで詳細ボトムシートを開き、削除は詳細ビューではなく編集フォーム側に残す
- 1023px以下の新規予定保存後はボトムシートを閉じる。既存予定の編集保存では開いたままにする
- 編集中の `リセット` は保存前の内容を破棄し、toast 履歴は作らない
- undo 対象は直近 1 件のみ
- undo toast は 8 秒で自動消滅する
- 全データ初期化は undo 対象にせず、実行前にブラウザ標準確認を挟む
- コピー失敗時は手動コピー用の文面を表示する
- Schedule Calendar 内のドロップダウンは、日付 / 時刻と同様にアプリ内の独自メニューUIで統一する
- 投稿補助テンプレートのハッシュタグは本文とは別に保存し、コピー時に保存済みハッシュタグセット、予定側ハッシュタグと重複排除して結合する
- 保存済みハッシュタグセットは設定で追加 / 編集 / 削除し、投稿補助プレビューで選択したセットだけを一時的に本文へ追加する
- 予定管理の告知ハッシュタグ欄は告知ステータスの下に置き、保存済みハッシュタグセットを独自メニューで選んで予定固有タグとして追記保存できる
- `{hashtags}` を本文に入れた場合はその位置へ結合済みハッシュタグを差し込み、本文にない場合は末尾へ追加する
- 不明な `{...}` 変数は置換せず、投稿前プレビューで気付ける状態にする
- JSON インポート失敗時は既存データを保持し、失敗メッセージを表示する
- 1023px 以下のモバイル統合 UI と、1024px 以上の右パネル UI は混線させない

## Known Environment Note

この Codex 環境では、`npm run lint`、`npx tsc --noEmit`、`next dev` などが Node 起動前に次のエラーで停止することがあります。

```text
Assertion failed: ncrypto::CSPRNG(nullptr, 0)
```

この場合は、ユーザー側 PowerShell で lint / typecheck を再実行し、Codex 側では `git diff --check`、静的差分確認、起動済みブラウザでの回帰確認を代替証跡として残します。
