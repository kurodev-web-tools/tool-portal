# ポータル情報設計と左サイドバー拡張方針

## 目的

`V_streamer_tools` のポータル画面における役割分担を整理し、初期MVPから将来のログイン後体験まで破綻しないナビゲーション設計を定義する。

このドキュメントでは特に以下を扱う。

- ポータル本体の責務
- 左サイドバーの責務
- 将来の個人カスタマイズ方針
- URL構成の考え方

## 基本方針

ポータルとサイドバーは同じ「ナビゲーション」ではあるが、役割は分ける。

- ポータル本体
  - スイート一覧を見る場所
  - 目的単位でツール群を発見する場所
  - どのスイートにどんなツールが属するかを把握する場所
- 左サイドバー
  - すぐ使う導線だけを置く場所
  - 実作業へのショートカットを担う場所
  - 将来的には個人最適化される場所

この分離により、ツール数が増えても一覧性と作業導線を両立できる。

## 段階的な左サイドバー方針

### Phase 1: 初期MVP

左サイドバーには `固定項目 + 実装済みツール` のみを表示する。

想定構成:

- Home
- Tools
- Schedule Calendar

この段階ではログインがないため、サイドバー内容は全ユーザー共通とする。

### Phase 2: ログイン導入後

サイドバーに `最近使ったツール` や `おすすめ` など、利用文脈に寄ったセクションを追加できる。

想定構成:

- 固定ナビ
  - Home
  - Tools
- 実装済みツール
  - Schedule Calendar
  - 他の公開済みツール
- Recent
  - 直近で使ったツール

この段階では、完全な自由編集までは行わず、利用履歴ベースの補助導線を追加する。

### Phase 3: 個人カスタマイズ

ログインユーザーごとに左サイドバーを個人設定として保持する。

想定機能:

- お気に入り登録
- ピン留め
- 並び替え
- 不要項目の非表示

最終的には、左サイドバーを `個人用ツールランチャー` として扱う。

## 情報設計上の役割分担

### ポータルTOP

役割:

- サービス全体を見せる
- スイート単位で入口を見せる
- どの目的にどのツール群があるかを示す

含める情報:

- サービス概要
- サマリー
- スイートカード一覧
- 必要なら代表ツールや件数

HOME では個別ツール一覧や細かい絞り込みは持たず、探索の詳細は `/tools` に送る。

### `/tools`

役割:

- 全ツールを一覧で比較する
- スイート / カテゴリ / 実装状態で絞り込む
- 個別ツールへ入る

含める情報:

- ツール一覧
- スイートフィルタ
- カテゴリフィルタ
- 実装状態フィルタ

HOME のスイートカードから `/tools` に入る場合は、選択したスイートで事前絞り込みされた状態で表示する。

### 初期スイート定義

初期MVPでは、HOME のスイートカードは以下の4分類を採用する。

1. 配信ワークフロー
   - key: `stream-workflow`
   - 元の大分類: `配信ワークフロー支援スイート`
   - 含む代表要素:
     - 企画・準備
     - 配信実行
     - 配信後処理・分析
2. ファン＆ブランド
   - key: `fan-brand`
   - 元の大分類: `ファンエンゲージメント＆ブランディングスイート`
   - 含む代表要素:
     - ファン交流
     - ブランディング・アイデンティティ確立
3. ビジネス＆コラボ
   - key: `business-collab`
   - 元の大分類: `ビジネス＆コラボレーションスイート`
   - 含む代表要素:
     - ビジネス・収益化
     - コラボレーション
4. 成長＆セルフケア
   - key: `growth-selfcare`
   - 元の大分類: `セルフマネジメント＆成長支援スイート`
   - 含む代表要素:
     - セルフマネジメント
     - 学習
     - 継続支援

UI では短い表示名を使い、内部参照や元資料との対応は `key` と元の大分類で保つ。

### HOME カード文言の初期案

- 配信ワークフロー
  - 企画から配信後の振り返りまで、日々の配信活動を支えるツール群
- ファン＆ブランド
  - ファンとの交流や世界観づくりを支え、活動の魅力を育てるツール群
- ビジネス＆コラボ
  - 収益化やバックオフィス、コラボ進行を整理するためのツール群
- 成長＆セルフケア
  - 学習、活動継続、セルフマネジメントを支えるツール群

### `/tools` への受け渡し方針

スイートカードの `開く` では `/tools` に遷移し、選択したスイートを初期状態として渡す。

例:

- 配信ワークフロー -> `/tools?suite=stream-workflow`
- ファン＆ブランド -> `/tools?suite=fan-brand`
- ビジネス＆コラボ -> `/tools?suite=business-collab`
- 成長＆セルフケア -> `/tools?suite=growth-selfcare`

`/tools` 側では、URL の `suite` を読んでフィルタを初期選択状態にする。  
その後はユーザーが自由にフィルタを変更できるようにする。

### 左サイドバー

役割:

- 今すぐ移動する
- よく使う画面に短距離で入る

含める情報:

- 固定ナビ
- 実装済みツールへのショートカット
- 将来的にはお気に入り / 最近使った項目

### 各ツール画面

役割:

- 実際の作業を行う
- 自分のデータに対して編集や管理を行う

ポータルの延長ではなく、`作業画面` として設計する。

## URL構成の考え方

初期MVPでは公開ポータルと個別ツールを明確に分ける。

### Phase 1

- `/`
  - ポータルTOP
- `/tools`
  - ツール一覧
- `/tools/schedule-calendar`
  - スケジュールカレンダーMVP

### Phase 2 以降

ログイン後の個人用領域を別に持つ。

- `/app`
  - ログイン後ホームまたは個人ダッシュボード
- `/app/tools/schedule-calendar`
  - ログイン後の個人用スケジュールカレンダー

この分け方により、公開ポータルと個人データを扱うアプリ領域を混同しない。

## 実装指針

- 初期段階では左サイドバーを固定構成で作る
- サイドバー項目のデータ構造は、将来 `favorite` や `pinned` を持てる前提で設計する
- ポータル側はスイート一覧を主とし、個別ツール一覧は `/tools` に集約する
- サイドバーはあくまでショートカットであり、完全な情報探索はポータル側に残す
- スイートカードは `/tools` への導線として機能し、対応スイートを初期選択状態で渡す

## 推奨UI構成

### 初期MVP

- Header
- Left Sidebar
  - Fixed
    - Home
    - Tools
  - Implemented Tools
    - Schedule Calendar
- Main Content
  - スイート一覧または各ツール画面

### 将来拡張

- Header
- Left Sidebar
  - Fixed
  - Pinned
  - Recent
  - Available Tools
- Main Content
  - ポータルまたは作業画面

## 結論

左サイドバーは、初期は `実装済みツールを固定表示` し、将来的に `ユーザーごとにお気に入りやよく使うツールを登録できる個人用ランチャー` へ拡張するのが最も無難である。

この方針なら、

- 初期実装が軽い
- ナビゲーションが分かりやすい
- ログイン機能追加後も自然に拡張できる
- ツール数増加時にも破綻しにくい

という利点がある。
