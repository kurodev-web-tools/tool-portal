# ギフティング連動・物理デバイス 設計書

## 1. システム構成図
- **クラウドバックエンド**:
    - **ストリームリスナー**: YouTube/TwitchのAPIに接続し、リアルタイムでチャットやギフトイベントを監視する。
    - **ルールエンジン**: データベースからユーザーの設定を読み込み、受信したイベントが条件に一致するか判定する。
    - **IoTコントローラー**: 条件に一致した場合、各IoTデバイスのAPIやプロトコル（MQTTなど）を介して、制御コマンドを送信する。
- **物理デバイス (IoT)**: VTuberの部屋に設置されるスマートデバイス。インターネット経由でクラウドバックエンドからのコマンドを待機する。
- **フロントエンド (Webダッシュボード)**: VTuberが連携する配信アカウントやIoTデバイスを設定し、ルールをカスタマイズするウェブインターフェース。

## 2. 主要機能詳細

### 2-1. イベント受信からデバイス制御までのフロー
- **ユーザーアクション（VTuber）**:
    1. ダッシュボードでYouTubeアカウントと、所有するスマートライト（例: Philips Hue）を連携させる。
    2. 「$10以上の赤いスパチャ」というトリガーに対して、「ライトを赤色で10秒間点滅させる」というアクションを紐付けてルールを保存する。
- **システム動作（配信中）**:
    1. ストリームリスナーが、配信中のYouTube Live Chat APIを監視。
    2. あるファンが$10の赤いスパチャを送信する。
    3. ストリームリスナーがこのイベントを検知し、イベントの詳細（ユーザー名、金額、色など）をルールエンジンに渡す。
    4. ルールエンジンは、データベースからVTuberの設定を照会し、条件に一致することを確認。
    5. IoTコントローラーが、Philips HueのAPIを呼び出し、指定されたライトを赤色で10秒間点滅させるためのHTTPリクエストを送信する。
    6. VTuberの部屋のライトが赤く点滅する。

### 2-2. デバイス連携
- **ユーザーアクション（VTuber）**:
    - ダッシュボードで「新しいデバイスを追加」を選択し、デバイスの種類（例: Philips Hue）を選ぶ。
    - 画面の指示に従い、デバイスメーカーのOAuth認証を行い、API経由での操作を許可する。
- **システム動作**:
    1. バックエンドが、デバイスメーカーのOAuth 2.0フローを実行し、アクセストークンを取得・保存する。
    2. 取得したトークンを使い、IoTコントローラーがそのユーザーのデバイスリストを取得し、制御対象のデバイスを選択できるようにする。

## 3. 技術スタック
- **バックエンド**: **Go**
- **データベース**: **PostgreSQL**, **Redis** (キャッシュ、キュー用)
- **IoT通信プロトコル**: **MQTT**, **HTTPS (REST API)**
- **クラウドサービス**: **AWS IoT Core** または **Google Cloud IoT Core**
- **フロントエンド**: **Next.js (React)**
- **UIフレームワーク**: **Tailwind CSS**, **shadcn/ui**

## 4. データベース設計
- **Users**: ユーザー情報。
- **StreamAccounts**: 連携された配信アカウント情報（YouTube, Twitchなど）と認証トークン。
- **ConnectedDevices**: 連携されたIoTデバイスの情報（種類、デバイスID、認証トークンなど）。
- **Rules**: ユーザーが設定したルール（TriggerType, TriggerCondition, ActionType, ActionParamsなど）。
