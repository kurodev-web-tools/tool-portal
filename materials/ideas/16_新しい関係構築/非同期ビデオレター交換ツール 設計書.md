# 非同期ビデオレター交換ツール 設計書

## 1. システム構成図
- **フロントエンド**:
    - **ファン向けUI (Web/Mobile)**: ビデオレターの録画・アップロード、決済画面。
    - **VTuber向けUI (Web)**: 受信したビデオレターを管理するダッシュボード、返信ビデオの録画インターフェース。
- **バックエンド（APIサーバー）**: ユーザー認証、ビデオデータのメタデータ管理、決済処理、通知（メール、プッシュ通知）の管理を行う。
- **動画処理サーバー/サービス**: アップロードされた動画のエンコード、フォーマット変換、サムネイル生成などを行う（例: AWS Elemental MediaConvert）。
- **ファイルストレージ**: 録画された動画ファイルを安全に保管する（例: AWS S3）。
- **データベース**: ユーザー情報、ビデオレターのメタデータ（送信者、受信者、ステータス、ファイルURLなど）、決済履歴を保存。

## 2. 主要機能詳細

### 2-1. ビデオレター送信フロー
- **ユーザーアクション（ファン）**:
    1. VTuberのページで「ビデオレターを送る」ボタンを押す。
    2. 料金を確認し、Stripeで決済を行う。
    3. ブラウザのマイク・カメラへのアクセスを許可し、ビデオを録画する（制限時間あり）。
    4. 録画内容を確認し、送信ボタンを押す。
- **システム動作**:
    1. 決済完了後、録画画面に遷移。
    2. 録画されたビデオデータは、フロントエンドから直接、またはバックエンド経由でファイルストレージにアップロードされる。
    3. アップロード完了後、バックエンドは動画のメタデータをデータベースに保存し、動画処理サーバーにエンコードのジョブを投入する。
    4. VTuberには、新しいビデオレターが届いたことが通知される。

### 2-2. ビデオ返信フロー
- **ユーザーアクション（VTuber）**:
    1. ダッシュボードでファンからのビデオレターを視聴する。
    2. 「返信する」ボタンを押し、返信ビデオを録画する。
    3. 録画内容を確認し、ファンに送信する。
- **システム動作**:
    1. VTuberの返信ビデオも同様にファイルストレージにアップロードされ、メタデータがDBに記録される。
    2. ファンには、VTuberから返信が届いたことが通知される。
    3. ファンは、専用の視聴ページ（認証付き）で返信ビデオを閲覧できる。ダウンロードは原則不可とする。

## 3. 技術スタック
- **フロントエンド**: **Next.js (React)**
- **UIフレームワーク**: **Tailwind CSS**, **shadcn/ui**
- **モバイルアプリ**: **React Native**
- **リアルタイム録画**: **WebRTC (MediaRecorder API)**
- **バックエンド**: **Python (FastAPI)**
- **動画処理**: **AWS Elemental MediaConvert**, **FFmpeg**
- **ファイルストレージ**: **AWS S3**
- **データベース**: **PostgreSQL**
- **決済**: **Stripe API**

## 4. データベース設計
- **Users**: ユーザー情報（VTuber/ファン 구분）。
- **VideoLetters**: ビデオレター情報（ID, SenderID, ReceiverID, Status, OriginalVideoURL, ReplyVideoURL, PaymentIDなど）。
- **Payments**: 決済情報（Stripeの取引IDなど）。
