# PLAN.md

## 概要

`V_streamer_tools` は、VTuber向けツール群を段階的に育てていくことを前提としたプロダクト群である。  
初回MVPでは、全体の入口となるポータルと、最初の実用ツールとしての `スケジュールカレンダー` を中心に構築する。

本計画では、いきなり個別ツール実装に入るのではなく、先にポータルと共通UIを固め、その上で個別ツールを追加していく方針を採用する。

## 直近の開発方針

### 方針

- 先にポータルを実装する
- ポータルで共通部分を固める
- その後にスケジュールカレンダーの詳細実装計画を詰める
- 実装は段階的に行い、認証や外部APIは後続フェーズへ送る

### この順序を採用する理由

- 共通UIを先に確定できる
- ツール追加時の設計ブレを減らせる
- 初回MVPでも「ツール群」の入口を見せられる
- スケジュールカレンダー実装時に、レイアウトや共通コンポーネントの再設計を避けられる

## フェーズ計画

### Phase 1: ポータル基盤と共通UI

目的:

- サービス全体の入口を作る
- MVPの見た目と共通構造を確定する

対象:

- ポータルTOP
- Header
- Left Sidebar
- Theme Toggle
- Hero Summary
- Suite Card
- Status Badge
- スイート入口としての状態表現

除外:

- ログイン
- 課金
- 個人設定
- お気に入り / Recent / Pinned の保存

完了条件:

- ポータルの正式モックに沿った画面が組めている
- 共通UIの基準が今後のツール画面でも流用できる
- `HOME = スイート一覧`、`/tools = ツール一覧` の責務分離が成立している

### Phase 2: スケジュールカレンダー詳細計画と実装

目的:

- 初回MVPの中核となる実用ツールを完成させる

対象:

- 左カレンダー + 右固定パネル構成
- 週表示初期
- 予定の追加 / 編集 / 削除
- `localStorage` 保存
- 投稿補助タブ
- コピー
- `X` 投稿画面遷移

除外:

- Google Calendar連携
- SNS API直接投稿
- アカウント同期
- AI生成機能

完了条件:

- 予定管理がローカルで完結する
- 投稿補助まで含めて1本のツールとして使える
- ポータルから自然に遷移できる

### Phase 3: ログイン後体験の導入

目的:

- 個人保存と個人最適化を導入する

対象:

- ログイン導線
- 個人用アプリ領域 `/app`
- サイドバーの `Recent / Favorites / Pinned`
- 将来の保存先としての Cloudflare 基盤検討

候補技術:

- Pages Functions
- Workers + D1/KV

### Phase 4: 他ツール追加

目的:

- ポータルを実際のツール群へ拡張する

対象:

- 新規ツール追加
- 実装済みツールの左サイドバー反映
- 将来的なツール横断導線の整理

## 情報設計方針

### ポータル

- スイート一覧を見る場所
- 目的単位でツール群を発見する場所
- `/tools` への入口になる場所

### `/tools`

- 全ツール一覧を見る場所
- スイート / カテゴリ / 実装状態で絞り込む場所
- 個別ツールへ入る場所

### 左サイドバー

- すぐ使う導線だけを置く場所
- 初期は `固定項目 + 実装済みツール`
- 将来的には `個人用ランチャー`

### 各ツール画面

- 実作業を行う場所
- ポータルの延長ではなく、作業画面として扱う

## URL構成の長期方針

### 初期

- `/`
  - ポータルTOP
- `/tools`
  - ツール一覧
- `/tools/schedule-calendar`
  - スケジュールカレンダー

### 将来

- `/app`
  - ログイン後ホーム
- `/app/tools/schedule-calendar`
  - 個人用スケジュールカレンダー

## デザイン方針

- 実務ダッシュボード寄り
- ライト / ダーク両対応
- 深めティール中心
- ミントは補助
- フラット + 薄い境界線
- 8px角丸
- 読みやすいサンセリフ
- やや高密度だが整理された画面
